# HTML・CSSコース生成

記事本文をlitehtmlでレイアウトし、DirectWriteで文字計測、Direct2DでD3D11テクスチャへ描画する。
依存バージョンは `cmake/WikiHtml.cmake` のコミットに固定する。初回CMake構成にはGitHubへのアクセスが必要。
オフラインでは `FETCHCONTENT_SOURCE_DIR_LITEHTML` に同コミットの取得済みソースを指定できる。
litehtmlおよび同梱Gumboのライセンスはビルド後に実行ファイル横の `licenses/` へコピーする。

## 処理

1. 既存の記事取得ワーカーで記事HTMLを取得する。
2. Gumboで解析し、本文構造・記事リンク・画像URLのみを再構築する。
3. 外部CSSとJavaScriptは使わず、`CourseCss()` の固定CSSを適用する。
4. 許可した画像をワーカーで取得・WICで縮小デコードする。
5. メインスレッドで画像ビットマップを作成し、文字計測とレイアウトは別ワーカーで実行する。
6. レイアウトを確定してからリンク・見出し・画像・表の領域を抽出する。
7. メインスレッドで最大512画素高のタイルを1回につき1枚描画する。
8. ホールと地形には同じ代表リンク矩形を渡す。HTML方式では画像・表が低い台地、見出しが低い盛り上がり、リンク周辺が平坦なグリーンになる。

リンクの表示矩形は改行ごとに保存し、その中で最大面積の矩形を代表位置にする。
同一リンク要素は1ホールとなり、リンク以外の同名文字列はホールにならない。
同じ遷移先でも別のリンク要素は別候補として扱う。目標記事を優先し、中心間4.25ワールド単位未満の候補を間引く。
選択後の同じ一覧を地形生成とホール生成へ渡す。リンクの表示位置は変更しない。
地形は全域を低い起伏に制限し、壁・水域による通路遮断は生成しない。
障害物を伴う経路探索・通路補正は今回の地形方式には導入していない。

## 上限・キャッシュ

- HTML入力: 2 MiB、HTML要素走査: 40,000ノード、深さ: 96。
- レイアウト幅: 2,048 CSS px。表などの実際のはみ出しも全幅に含める。
- 最大レイアウト高さ: 500,000 CSS px。
- 出力テクスチャ: 32 Mi pixels、BGRA8で最大128 MiB。解像度だけ下げ、記事を途中で切らない。
- 画像: 最大12 URL、1通信8 MiB、縮小後最大辺2,048、合計48 MiBのデコード済み画素。
- キャッシュ: プロセス内・最大2記事・合計128 MiB。テクスチャと領域を一緒に保持する。
- キャッシュキー: 整形済みHTML、目標記事、画像URL・寸法・画素のハッシュ。
- 現在のコースとキャッシュは同じGPUリソースを共有する。別記事の生成中は現在の生成分に加えキャッシュの最大128 MiBが残り得る。
- キャッシュは再起動をまたがず、ネットワーク取得そのものは省略しない。

HTML生成失敗時には従来のテキスト方式へ戻る。上記のテクスチャ上限はHTML方式に適用する。
チュートリアルは固定教材レイアウトを保つためテキスト方式を使う。
コースの縦横比はCSSレイアウト寸法から決め、出力倍率の丸めで変化しない。

## ビルドと検証

通常のWindowsビルドでは `WIKIGOLF_HTML_COURSES=ON` が既定。
従来方式のみでビルドする場合:

```powershell
cmake -S . -B build -DWIKIGOLF_HTML_COURSES=OFF
```

DirectXに依存しないレイアウト・URL処理・地形ルールの検証:

```sh
cmake -S . -B build-html -DWIKIGOLF_HTML_TESTS_ONLY=ON
cmake --build build-html --config Release --parallel 4
ctest --test-dir build-html -C Release --output-on-failure
```

Windowsで同じ設定を使うと、WARPによる `course_html_d3d` も構築する。
日本語リンク、非リンク文字列、タイルの連続性、画素上限、GPU読み戻しによる非白色画素、繰り返し生成を検証する。
Linuxでは文字計測用のテスト実装を使うため、DirectWriteの字形や実GPU性能は検証しない。

## 残る実機確認

- 日本語フォント・表・画像回り込みの見た目とリンク位置。
- HTML方式とテキスト方式のロード時間、生成中のフレーム時間、最大メモリの比較。
- 長文・巨大表・画像多数の記事を使った可読性とゲームとしてのコース長。
- 密集箇所での間引き量と、残ったリンク選択肢の遊びやすさ。
- 日本語禁則処理や複雑なCSSのブラウザ完全互換は対象外。
