# 芝描画の作り替え設計（GPU 駆動・手続き的な葉の配置）

対象：ラフ・セミラフ・フェアウェイ・グリーンの 3D の芝（タイトル画面の芝を含む）。
状態：検討段階。数値はコードの設定値から出した概算で、実測していない。

---

## 1. 目的

1. GPU 負荷を大きく下げる。特に Ultra/ExHigh で、見た目を保ったまま芝の三角形数を数分の 1 にする。
2. CPU 側の芝の処理を、毎フレームほぼゼロにする（インスタンス単位のループ、毎フレームのインスタンス転送、チャンクのストリーミング生成、チャンク境界でのひっかかりをなくす）。
3. 見た目をより自然にする（四角いパッチ感、画面上のディザー模様、まだらなセミラフ、境界の直線感をなくす）。
4. **近距離の密度を今の 2〜4 倍に上げ、規則的な並びが見えない「密に詰まった本物の芝」にする**（6 章）。上げた分の負荷は、画面上の大きさに合わせた LOD で吸収する。

## 2. 現状の構造と限界

| 段階 | 現状 | 問題 |
|---|---|---|
| 配置 | CPU が 12m チャンクごとに、葉入りのパッチ（メッシュ）をインスタンスとして並べる。ラフはパッチを 1.7 倍に拡大して重ねる | 同じ地面を平均約 1.8 枚のパッチが覆う。境界はパッチ単位の確率で間引くので、まだらで四角くなる |
| ストリーミング | カメラ周辺のチャンクを 1 フレーム 512 インスタンスずつ生成し、範囲外を破棄する | 境界をまたぐたびに `m_entities` と `m_grassPatches` 全体を `remove_if` するので、ひっかかる |
| 絞り込み | 毎フレーム、全候補インスタンスについて距離・見下ろし角・境界球を CPU で判定し、ポリゴン上限をヒストグラムで解く | Ultra では数万インスタンスを毎フレーム処理している |
| 転送 | 描画インスタンスごとに 160 バイト（行列 2 つ＋色＋Flags）を Map で書き込む | 1 万インスタンスで約 1.6MB/フレーム |
| LOD | パッチのメッシュを近距離と LOD の 2 段で切り替える | 短い芝が 1 ピクセルより細い三角形の山になる（Ultra のフェアウェイは 1m² あたり約 8,400 枚） |
| 頂点 | 風・突風・つむじ風・余波を頂点ごとに解析的に計算する。速度バッファ用に前フレームの時刻でもう一度計算する | 葉 1 枚は 3 頂点で共有なし。sin 10 個以上が 2 回分 |
| ピクセル | 距離フェードを画面上のディザーと `clip()` で行う。カップも `discard`。影は 9 点の PCF | early-Z が効かない。ディザー模様が見える |
| 接触 | パッチごとに 1 つの接触点と角度を持ち、CPU が毎フレーム全パッチを走査する | Ultra で 10 万前後のパッチを毎フレーム走査している |

パッチをインスタンスとして CPU で管理する方式そのものが、上の問題の大半の原因になっている。そこで、**葉の位置を GPU がワールド座標から手続き的に決める方式**へ切り替える。

---

## 3. 新方式の全体像

```
[コース構築時・CPU 1回]                 [毎フレーム・GPU]
TerrainData                              ┌ WindCS     : 風テクスチャ（今回分・前回分）
  ├ heightMap  ─┐                        ├ TrampleCS  : 踏み跡テクスチャ（ボール周辺）
  ├ normals     ├→ GrassFieldBuilder ─→ ├ CullCS     : タイル単位の視錐台判定・LOD 振り分け
  ├ materialMap │    （純粋な CPU 処理） │              → LOD ごとの追記バッファ
  └ visual色   ─┘    ↓                   ├ CopyStructureCount → 間接描画の引数
           GrassFieldSource（ECS global）├ ExpandCS   : 近距離の葉を 1 枚ずつ展開
                     ↓ 初回 / 変更時     └ GrassFieldVS/PS : 頂点バッファなしで葉を生成して描画
           GrassFieldGpuState（テクスチャ・バッファ）
```

- 葉は**ワールドに固定されたタイル**（ラフ 2m、短い芝 1m）の中に、低食い違い列で決まる位置へ生える。タイル同士は重ならず、隙間なく並ぶ。
- 生やすかどうか、丈・色・種類は、葉の根元の位置で**フィールドテクスチャ**を読んで葉ごとに決める。境界はパッチ単位ではなく葉単位でなめらかになる。
- CPU は毎フレーム定数バッファを 1 つ更新し、コンピュートシェーダー数回と間接描画を十数回発行するだけになる。

## 4. データ（コース構築時に 1 回作る）

### 4.1 GrassFieldBuilder（新規・純粋な CPU 処理・単体テスト対象）

入力は `TerrainData` とグラフィックプリセット。出力は次の配列で、ECS の global である `GrassFieldSource` に入れる。components の分離原則に合わせ、中身は純粋なデータだけにする。

| テクスチャ | 形式 | 解像度 | 内容 |
|---|---|---|---|
| Height | R32_FLOAT | 地形と同じ（0.8m、最大 160×2048） | `heightMap` そのもの。VS で 4 点読んで双線形補間し、CPU の `GetHeight` と同じ式にする |
| Normal | R8G8B8A8_SNORM | 地形と同じ | `normals`。坂に沿って葉を傾けるのに使う |
| Field | R8G8B8A8_UNORM | **0.4m/テクセル**（最大 320×4096 で約 5MB） | R：ラフの丈係数（ラフ 1、セミラフ帯 0.45〜0.6、その他 0）／G：フェアウェイ重み／B：グリーン重み／A：生えてよい度合い（バンカー・水・溶岩・氷・石畳は 0。境界は柔らかく） |
| Tint | R8G8B8A8_UNORM | 地形と同じ | `visualMaterialColors`。地形と同じ下地色を葉にも使い、3D の葉から地形へ切り替わる所の色の段差をなくす |
| TileInfo（層ごと） | R16G16B16A16_FLOAT | ラフ 2m／短い芝 1m | x,y：タイル内の最低・最高の高さ／z：その層の最大密度（0 なら空タイル）／w：予備 |

フィールドの作り方：
1. `materialMap` を 0.4m 格子へ最近傍で拡大する。
2. 2 パスの距離変換で「ラフまでの距離」と「芝不可の地面までの距離」を求める。
3. セミラフは**フェアウェイ側でラフから 0〜1.5m の帯**として連続的に決める。今の「確率 62% で置く」方式は廃止する。
4. 芝不可の地面との境界は、距離に応じて A を 0→1 へなだらかに上げる（約 0.3〜0.6m）。
5. 小さなガウスぼかしで段差を消す。

コースは最大 160×2048 頂点なので、処理は数 ms の見込み。既存の複数フレームに分けた構築工程（`CreateSurfaceGrass`）の 1 ステップに置き換える。重い場合はワーカースレッドへ移す。

### 4.2 GPU 資源（GrassFieldGpuState・`ShadowRenderState` と同じく global に持つ）

- 上のテクスチャの SRV
- 風テクスチャ 128×128 RGBA16F ×2（今回分・前回分を交互に使う）。1m/テクセルでカメラ周辺 128m 四方を覆う
- 踏み跡テクスチャ 256×256 RGBA8。6.25cm/テクセルでボール周辺 16m 四方を覆い、ワールド座標に固定してラップアドレスで使う
- 見えるタイルの追記バッファ（層ごと × LOD ごと。それぞれ最大タイル数 × 8 バイト）
- 間接描画の引数バッファ（層 × LOD 分）
- 曲がった葉用の静的インデックスバッファ（LOD0 は 1 枚 7 頂点・5 三角形、LOD1 は 5 頂点・3 三角形のパターンを、最大枚数分並べたもの）
- LOD0 の葉データバッファ（6.3。16 バイト × 最大約 15 万枚 ≒ 2.4MB）

`GrassFieldSource` の版番号が変わったとき（コース切り替え・プリセット変更）だけ作り直す。

## 5. 毎フレームの処理

### 5.1 CPU（RenderSystem から呼ぶ。シーンのレンダーターゲットと速度ターゲットが付いている間）

1. 定数バッファを更新する（カメラ、視錐台の 6 平面、時刻、前フレームの時刻、風向・風速、LOD 距離、プリセット係数、GPU 負荷による距離倍率、風テクスチャの原点の今回分と前回分）。
2. WindCS → TrampleCS → CullCS（層ごと）→ ExpandCS（LOD0 のタイルだけ、6.3）を発行する。ExpandCS は CullCS が追記した LOD0 のタイル数から `DispatchIndirect` で起動する。
3. `CopyStructureCount` で、各追記バッファの件数を間接描画の引数の InstanceCount へ写す。
4. 葉を描く。**近い LOD から遠い LOD の順**に描くと、おおまかに手前から奥の順になる。
5. その後に通常の不透明物（地形を含む）を描く。地形の重い PS のうち、葉に隠れた部分は early-Z で捨てられる。

CPU の負荷は、層と LOD の数だけの API 呼び出し（20 回程度）になり、インスタンス数には依存しない。

### 5.2 CullCS（タイル判定）

- カメラのタイルを中心に、層の最大距離ぶんの正方形の範囲をスレッドで覆う（ラフは 2m タイルで 56m なら 57×57、短い芝は 1m タイルで 21m なら 43×43）。リストは持たず、スレッド ID からタイル座標を計算するので、**ストリーミングも空間インデックスも不要**になる。
- TileInfo を読み、z=0 なら終了する。高さの最小・最大に葉丈を足した AABB で視錐台判定する。
- **タイル内でカメラに最も近い点の距離**で LOD を決める（5.4 の連続性の条件）。見下ろし角でフェードしきるタイルも捨てる。
- カップの開口部と重なるタイルにはフラグを立てる。VS は、フラグのあるタイルだけでカップの判定ループを回す。
- 追記する内容は、タイル座標（16 ビット ×2）とフラグの 8 バイト。

### 5.3 GrassFieldVS（頂点バッファなし・SV_VertexID と SV_InstanceID だけ）

1. `tile = g_visibleTiles[SV_InstanceID]`、`blade = SV_VertexID / 頂点数`、`corner = SV_VertexID % 頂点数`。D3D11 の SV_InstanceID は StartInstanceLocation を含まないため、LOD ごとに別のバッファを読む。
2. 根元の位置：茎（シュート）単位で決める（詳細は 6.2）。シュートの中心は `frac(R2(shoot) + Hash(tile)) * タイル幅 + タイルの原点` に大きめのジッターを足したもの。R2 列は先頭 N 個を取っても均一に散らばるので、**LOD は先頭から何本描くかを変えるだけ**で済み、低い LOD は高い LOD の部分集合になる。乱数は整数ハッシュ（PCG 系）を使い、今の `sin` 由来のハッシュで出る縞状の相関を避ける。
3. Field と Tint を読み、`density = A × 層の重み` とする。`Hash(blade) > density` なら、その葉を大きさ 0 に潰す。
4. 高さは Height を 4 点読んで双線形補間し、坂の向きは Normal から取る。根元は 1cm だけ地中へ沈め、地形メッシュ（三角形で線形）との差を隠す。
5. 葉の形：丈・幅・傾き・向きは、層の基準値に Field の重みと葉ごとのハッシュを掛けて決める。ラフは 6.2 の株単位のまとまりを足す。近い葉は 6.3 の展開済みデータを読む。
6. 風：今回分の風テクスチャを 1 回読み、`xy × 柔らかさ × 穂先の重み` で変位させる。細かい揺れだけ VS で sin 2 つを計算する。速度バッファ用には前回分の風テクスチャを 1 回読むだけで済み、今の 2 回目の `DeformGrass` は不要になる。
7. 踏み跡：踏み跡テクスチャを読み、倒れる向きと量を加える。
8. フェード：距離・見下ろし角・LOD の切り替えのいずれも、**葉単位で縮めて消す**。PS の `clip()` とディザーは廃止する。
9. 法線は葉幅方向に丸め（texCoord.x で左右に回す）、穂先ほど上を向かせる。影の座標と、遠い LOD では頂点ごとの影の値を出力する。

### 5.4 LOD とつなぎ目

| LOD | ラフ（Ultra・2m タイル） | 短い芝（Ultra・1m タイル） | 葉の形 |
|---|---|---|---|
| 0 | 4,000/m²（今の約 3.6 倍） | 20,000/m²（今の約 2.4 倍） | 6.3 の CS で展開した、曲がった葉（7 頂点・5 三角形） |
| 1 | 1/2 | 1/2 | 5 頂点・3 三角形 |
| 2 | 1/4 | 1/4 | 1 三角形 |
| 3 | 1/8 | 1/8 | 〃 |
| 4 | 1/16 | 1/16 | 〃 |
| 5 | 1/32 | 1/32 | 〃 |

- **全密度を保つ距離 r0** は、葉 1 枚の幅がちょうど 1 ピクセルになる距離にする。1080p・縦の画角 60° では、幅 2.5mm の短い芝で約 2.3m、幅 5mm のラフで約 4.7m。それより遠くでは、密度を (r0/距離)² で減らし、間引いた分だけ葉幅を広げる。こうすると、画面上の葉の太さと被覆率がどの距離でもほぼ一定になる。
- この規則なら、全体の本数は `ρ0 × r0² × (1 + 2 ln(最大距離 / r0))` に比例する。近距離の密度 ρ0 を上げても、増えるのは近い範囲がほとんどになる（6.1）。
- LOD k のタイルでは、LOD k+1 で消える葉（後ろ半分）を、葉自身の距離に応じて切り替え距離へ向けて縮める。残る葉の幅も距離の連続関数で広げる。
- タイルの LOD は「タイル内の最も近い点」で決めるので、切り替え距離より手前の葉は必ず LOD k 以上のタイルに入っている。隣のタイルと LOD が違っても、葉単位の見た目は連続する。
- プリセットの差は、LOD0 の密度、切り替えを始める距離、最大距離の 3 つで表す。GPU の時間から倍率を決める今の `GrassGpuLoadController` はそのまま残し、距離倍率として定数バッファへ渡す。CPU 側でインスタンスを集める三角形上限の計算（`SolveGrassDrawBudget`）は廃止する。

### 5.5 GrassFieldPS

- 照明は今の GrassPS を引き継ぐ（両面の拡散光、透過光、根元の AO、葉面の光沢、フォグ）。
- `discard` がなくなるので、`[earlydepthstencil]` が効く。
- 影は LOD0〜1 だけ PS で求め、9 点を `GatherCmp` 1〜2 回へ減らす。LOD2 以降は VS で求めた値を補間して使う。この 2 種類は、PS の変種（define）として分ける。

### 5.6 WindCS・TrampleCS

- **WindCS**：今の `DeformGrass` から、風の帯・突風の包絡・つむじ風・余波（数 m〜数十 m 単位）をそのまま移し、テクセルのワールド座標で評価する。原点を 1m 単位へ寄せるので、カメラが動いてもちらつかない。1 フレーム 16K スレッドで済む。
- **TrampleCS**：ボールが芝に触れている間、前フレームから今フレームの位置までのカプセルを書き込み（向き＝進行方向、量＝速度に応じる）、全体を時間で減衰させる。ボール周辺へ新しく入った行と列は消去する。今のパッチ単位の接触より細かい**踏み跡の筋**が残り、ゆっくり起き上がる。CPU の `UpdateSurfaceResponse` の全パッチ走査はなくなり、CPU 側はボールの今の位置と前の位置を渡すだけになる。

## 6. 密に詰まった本物の芝にする

### 6.1 密度と負荷

本物の芝は 1m² あたり数万本の茎があり、そのまま 1 本ずつ描くことはできない。ただ、密に見えるかどうかを決めるのは、**葉が 1 枚ずつ見分けられる近い範囲（数 m 以内）の本数**と、**それより遠くで地面が透けず、葉の集まりとして陰影が付いていること**の 2 つである。そこで、近い範囲だけ本数を大きく増やし、遠くは画面上の太さを保ったまま本数を減らす。

90° の視野で見える本数の概算（5.4 の規則。最大距離はラフ 52m、短い芝 21m）：

| 層 | 近距離の密度 ρ0 | r0 | r0 以内の本数 | それより遠くの本数 | 合計 |
|---|---|---|---|---|---|
| 短い芝（今と同じ密度相当） | 8,400/m² | 2m | 2.6 万 | 12.4 万 | 15 万 |
| **短い芝（提案）** | **20,000/m²** | 2m | 6.3 万 | 29.5 万 | **36 万** |
| ラフ（今と同じ密度相当） | 1,100/m² | 6m | 3.1 万 | 13.4 万 | 17 万 |
| **ラフ（提案）** | **4,000/m²** | 4m | 5.0 万 | 25.8 万 | **31 万** |

- 画面に写る地面は、ラフかフェアウェイのどちらかでほぼ占められ、2 つの層が重なるのは境界の帯だけである。そのため 1 フレームの合計は、多い方の層の数字にほぼ等しい。
- 近い葉は複数の三角形で曲げても、三角形は**全部で 40〜50 万程度**に収まる見込み。今は要求約 390 万を上限 300 万で削っているので、その 1/6〜1/8 程度で、近距離の密度は 2.4〜3.6 倍になる。
- High 以下は ρ0 と最大距離を下げる。r0 は葉幅で決まるので、プリセットでは変えない。

### 6.2 並びを規則的に見せない

| 要素 | やり方 |
|---|---|
| 茎（シュート）単位 | 1 本のシュートから 2〜4 枚の葉を出し、根元を数 mm 以内に集めて扇状に少し開かせる。1 枚ずつ均等に並べるより、本物の芝の「小さな束の集まり」に見える |
| シュートの散らばり | R2 列の点に、間隔の 0.5〜0.7 倍のジッターを足す。格子にも完全な乱数（偏りすぎて地面が透ける）にもならない、中間の散らばりにする |
| 密度ムラ | シュートの密度を、0.3〜2m 単位の低い周波数のノイズで ±25% 程度揺らす。厚い所と薄い所が少し混ざる |
| 株のまとまり（ラフ） | 0.3〜0.6m のセルごとに、丈・寝る向き・色の偏りを共有させる |
| 繰り返しをなくす | メッシュのバリアントをやめ、すべてタイルの整数座標と葉の番号から整数ハッシュで決める。同じ並びは二度と出ない |
| 境界のゆらぎ | Field を読む位置を、低い周波数のノイズで数十 cm ずらす。記事レイアウト由来の直線的な境界が、刈り際の不規則な線になる |

### 6.3 近距離の葉を CS で先に展開する

近い葉（LOD0）は本数が多く、曲げるので頂点も多い。VS で毎頂点ハッシュやテクスチャ読みをやり直すと、1 枚あたりの計算が 7 倍になる。そこで LOD0 のタイルだけは、**ExpandCS が葉 1 枚ずつのデータ**（位置・向き・丈・幅・曲がり・色を 16 バイトに詰めたもの）を先に書き出す。VS は 1 回読んで曲線を組み立てるだけにする。

- 対象は近い範囲だけ（ラフ約 5 万枚＋短い芝約 6 万枚）なので、バッファは 2MB 程度で済む。
- LOD0 はさらに距離で 2〜3 段に分けた追記バッファに入れ、近い段から描く。密な芝の重ね描きでは、early-Z で後ろの葉の PS を捨てられるかどうかが効くため。

### 6.4 葉の形

- 近距離は 3 分割の曲線で、根元は太く先は細くし、少しねじる。
- 長さは対数正規分布でばらつかせる。ラフは長い葉ほど垂れ、数 % は途中で折れて寝る。
- フェアウェイとグリーンは葉先を刈り揃えて丈のばらつきを小さくし、切り口を少し白っぽくする。葉は刈り向きへ寝かせる。
- 刈り込みの縞は、葉が寝る向きと照明から自然に出るようにする（順光と逆光で明暗が入れ替わる）。地形側の縞も同じ式に揃える。

### 6.5 色と陰（「密度がある」と感じさせる中心）

- **キャノピー内の陰**：葉の中での高さと、その場所の密度から、下層ほど暗くする。密な芝は根元が影になり、地面がほとんど見えない。今の根元 AO を、密度に比例して深くするよう拡張する。
- **地面を見せない**：3D の芝がある範囲では、地形の色を芝の根元の色（暗い緑褐色のサッチ）へ寄せる。葉の隙間から明るい地面が見えると、すかすかに見えるため。
- **葉ごとのばらつき**：色相と明度を葉ごとに少し変える。下層の古い葉は黄ばませ、ラフには 2〜5% の枯れ葉を混ぜる。
- **光**：半透過で穂先を明るくし、弱い葉面光沢を付ける。今の GrassPS を引き継ぐ。
- **遠くでは平均へ寄せる**：距離とともに、葉ごとの色・明るさのばらつきを平均値へ寄せる。細い葉の明暗が画面上でちらつかず、遠くの地形シェーダーの短芝表現へ切り替わる所も目立たなくなる。地形シェーダーは、その平均値を視点の角度ごとに再現する（低い視点ほど葉先の色）。

### 6.6 揺れ

- 長い葉ほど大きく揺らし、刈り込んだ短い芝はほぼ揺らさない。
- 同じシュートの葉は、揺れの位相を少しだけずらす（束として揺れつつ、完全には揃わない）。

## 10. 危険と対策

| 危険 | 対策 |
|---|---|
| 根元が地形から浮く・埋まる（描画される地形は三角形で線形、葉は双線形） | 今の方式にも同じ差がある。根元を 1cm 沈め、葉の下端の色を地形へ寄せる |
| 追記の順が手前から奥にならず、重ね描きが増える | LOD の順に描くので、おおまかには手前から奥になる。足りなければ CullCS のスレッド順をカメラ中心からのリング順にする |
| 遠くの葉を太らせすぎて、帯状に見える | 葉の画面上の幅の目標値を調整できるようにし、プリセットごとに決める |
| パッチの「こんもり感」がなくなり、平板に見える | 株単位のまとまり（6.2）で丈と傾きに塊を作る |
| TAA／DLSS で細い葉がちらつく・残像が出る | 速度は前回分の風テクスチャで正しく出す。踏み跡の変化は遅いので今回分で代用する |
| 低性能 GPU（機能レベル 11_0）での CS・間接描画 | どちらも 11_0 の必須機能。Intel の内蔵 GPU で段階 1 の時点で確認する |
| Debug レイヤーの資源の重複バインド警告 | 各パスの後で UAV と SRV を外すことを GrassFieldRenderer の規約にする |
| 非常に長いコース | Field は 0.4m で縦 6,553m まで 16384 テクセルに収まる |
| 高密度にした近距離で、重ね描きによる PS の負荷が増える | LOD0 を距離で 2〜3 段に分けて近い段から描く（6.3）。PS は `discard` なしで early-Z が効く。足りなければ LOD0 だけ深度だけの事前描画を足す |
| 細い葉が密に並び、遠くでざらつく・ちらつく | 葉の画面上の幅を 1 ピクセル以上に保ち（5.4）、遠くでは葉ごとのばらつきを平均へ寄せる（6.5） |
| 葉を増やしても地面が透けて見える | 地形の色を芝の根元の色へ寄せ、キャノピー内の陰を密度に比例させる（6.5） |

## 11. 決めてほしいこと

1. **見える距離**は今と同じにし、近距離は 6 章の高密度（ラフ 4,000/m²、短い芝 20,000/m²）、遠くは画面上の太さに合わせて間引く案で進めてよいか。ρ0 と r0 は調整項目として残し、段階 3 で見ながら決める。
2. **踏み跡が残ってゆっくり戻る演出**を入れるか：今は接触が離れるとすぐ戻る。
3. **移行期間の比較用切り替え**をデバッグビルドだけに置くか、設定画面にも出すか（推奨はデバッグビルドだけ）。

## 12. 実装結果（設計からの変更点）

実装は段階を分けずに一度で置き換えた。旧方式（`GrassRenderBatch`、`GrassVS/PS.hlsl`、芝パッチのメッシュ、ストリーミング）は削除済みで、比較用の切り替えは置いていない。

### 設計から変えたところ

| 項目 | 設計 | 実装 |
|---|---|---|
| 間接描画の引数 | Append バッファ + `CopyStructureCount` | 判定 CS が引数バッファの InstanceCount を `InterlockedAdd` で直接数える。引数は毎フレーム `UpdateSubresource` で作り直す |
| 近距離の葉の展開（6.3） | ExpandCS で先に展開 | 入れていない。VS が葉ごとに形を求める。CS で葉ごとに1回だけ形を作り、生きた葉だけ詰める版を試したが、GPU 時間は変わらず（タイトル 4.93→4.96ms）、葉のバッファに最大 98MB 使ったのでやめた。重いのは形の計算ではなく、細い三角形の描画と塗り |
| 消える葉の扱い | — | 判定 CS がタイルごとに「最も近い点の目標密度 × 層の最大密度」から生き残りうるシュート数の上限を求め、見えるタイルに添える。VS はそれより後ろの葉を、形を作る前に捨てる |
| 短い芝の葉の形 | LOD0 は 7 頂点・5 三角形 | どの距離でも 1 三角形（`GrassShapeLod`）。数 cm の葉では曲がりが見えない |
| 芝の影 | 9 点の PCF | 比較サンプラーの 2x2 補間を 1 回だけ読む |
| 色テクスチャ（Tint） | 地形の色を焼いたテクスチャ | 入れていない。旧方式と同じ種類ごとの色（ラフ・セミラフ・フェアウェイ・グリーン）に、葉ごと・数 m 単位のまだらを掛ける |
| 全密度を保つ距離 r0 | ラフ 4m、短い芝 2m（全プリセット共通） | プリセットごと。ラフ 6/8/10/12m、短い芝 3/4/5.5/7m（MEDIUM/HIGH/EXHIGH/ULTRA）。4m ではタイトル画面のように見える地面がすべて遠い場面で葉がほぼ残らなかった。短い芝は最初 2/2.5/3/4m にしたが、フェアウェイとグリーンが薄く見えたので広げた |
| 遠くの葉幅の補い | 1/√t（上限 3 倍） | t^-0.75（上限 6 倍、`GrassWidthScaleForDensity`）。1/√t では被覆が √t で減り、遠景が地面だけに見えた |
| 短い芝の密度 | HIGH 8,000、EXHIGH 12,000 /m² | HIGH 10,000、EXHIGH 16,000 /m²（EXHIGH でグリーンがまばらに見えたため） |
| 見下ろしたときの見た目 | 短い芝は真上で地形へ任せる | 見下ろすほど葉を最大 2.4 倍に広げ、倒れを最大 1.8 倍にする。グリーンだけは真上に近づくほど（|視線の y| 0.60〜0.85）高さと幅を 0 まで縮めて消す |
| バンカー・水の縁 | 生やさない所からの距離で柔らかく減らす | 生やさない格子の中心から 0.55m で生え始め 1.3m で生えそろう（地形の色は 0.8m の頂点の間で混ざるため）。ぼかしは元の値を超えないようにして染み出しを防ぐ。縁の葉は短く起こす（高さ 0.35 倍・倒れ 0.4 倍まで）。フィールドを読む位置のゆらぎは ±0.15m |
| 無風のとき | — | 風のテクスチャに、うねりながら渡る弱いそよ風を常に足す（葉先 1〜3.4cm）。葉ごとの揺れも最低 9mm にする |
| ショットへの反応 | — | ショット・着地・カップインを `GrassImpulseEvents`（最大 8 個）に積み、VS が葉先のずれを足す。ショットは打つ向きへなびいて揺り返し、着地は外へ押し倒す輪が広がり、カップインは 3 重の波。短い芝も見えるよう、しなやかさを 0.45 以上として扱う |
| 踏み跡の戻り | 時定数 1.2 秒 | 3 秒（旧方式は軌跡を 10m 残していたため、すぐ戻ると物足りない） |
| 芝の後片付け | — | World はシーンをまたいで共有されるので、タイトルとゲームの終了時に `ClearGrassField` で元データと GPU 上のフィールドを消す（消さないとロード画面にタイトルの芝が残った） |

### 計測（RTX 4070 Laptop 8GB、AUTO → EXHIGH、MSAA 4x）

| 場面 | 旧方式 GPU.Meshes.Grass | 新方式 GPU.Meshes.Grass | 新方式 GPU.Grass.Compute |
|---|---|---|---|
| タイトル画面（放置 50 秒） | 平均 2.59ms | （r0 変更前の版で 0.07ms。葉がほぼ残っていなかったため参考外） | 0.03ms |
| 実プレイ（チュートリアル、手動操作） | 平均 1.39ms / p95 2.47ms | 平均 1.16ms / p95 2.70ms | 平均 0.18ms / p95 0.57ms |
